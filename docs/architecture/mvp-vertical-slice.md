# MVP縦切り

## 狙い

現行のスクリーンショット貼付とコメント作成をいきなり本番APIへ置き換えず、再現性と責任分離を先に検証する。CSVの列が将来のBigQuery/GA4アダプターの共通契約になる。

```text
sanitized CSV + context + reusable profile
              |
              v
      deterministic validation
              |
              v
      facts.json / facts.md
              |
              +------> LLM packet ------> comment draft
              |                              |
              v                              v
        draft report ----------------> human review
                                             |
                                   approved only
                                             v
                                        final report
```

## 責任境界

| 層 | 行うこと | 行わないこと |
| --- | --- | --- |
| Python | 入力検査、分類適用、集計、期間比較、候補抽出、ハッシュ | 欠損推測、原因断定、媒体変更 |
| LLM | 事実要約、仮説、改善案、確認事項、顧客向け表現 | KPI計算、数値変更、実行済みの捏造 |
| 人間 | 商材分類、案件文脈、解釈、顧客表現、改善案、確定版の承認 | 生成されたことを承認とみなすこと |

## なぜ日立システムズ専用にしないか

複数商材・多数キャンペーン・GA4併用という難しさはfixtureで再現するが、キャンペーン名と商材分類はプロファイルへ切り出す。初回だけ人間が分類し、翌月は同じプロファイルを再利用する。新しいキャンペーンが現れたら止まり、再確認する。

## パートの増減

プロファイルの `sections` で、商材別、キャンペーン別、検索語句、次アクション等を選ぶ。固定の巨大テンプレートを全案件へ押し付けない。一方で事実正本は同じため、表示を外してもデータの追跡性は保つ。

## 次の実装境界

1. 実レポートのCSVと合成fixtureの列対応を確認
2. BigQuery SQLのread-only実行結果を同じ正規化契約へ変換
3. GA4の閲覧権限・認証方式を案件単位で設計
4. 近藤さんの分析プレイブックを参照正本として接続
5. 既存スライドテンプレートへ編集可能なオブジェクトとして配置
6. PDF/画像レンダリング、全ページ目視検査、元レポートとの差分評価

ABS案件のような顧客実数との突合は、この縦切り完成後の別評価ケースとする。
